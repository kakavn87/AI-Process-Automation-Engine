LiteLLM und Open WebUI verbinden

Serverseitig

Für die lokale Umgebung ist eine Docker-Compose-Konfiguration enthalten. Bei einer Bereitstellung auf Render müssen LiteLLM, Open WebUI und Qdrant als separat erreichbare Dienste betrieben werden. Die Adresse localhost funktioniert dort nicht als Verbindung zwischen getrennten Diensten.

Backend-Umgebungsvariablen 
AI_GATEWAY_PROVIDER=litellm
OPENAI_BASE_URL=https://<litellm-host>/v1
OPENAI_API_KEY=<virtueller-backend-schluessel>
OPENAI_MODEL=process-analysis
OPENAI_VISION_MODEL=process-vision
RAG_EMBEDDING_MODEL=process-embeddings
OPENWEBUI_URL=https://<open-webui-host>
RAG_ENABLED=true
Lokaler Start 
cd infrastructure/docker
cp .env.ai-platform.example .env.ai-platform
docker compose --env-file .env.ai-platform --profile ai-platform up -d

Erstellen Sie in LiteLLM getrennte virtuelle Schlüssel für Backend und Open WebUI. Hinterlegen Sie die Schlüssel nur in den jeweiligen Server-Umgebungen.

Sicherheit: Verwenden Sie für FlowPilot und Open WebUI jeweils eigene, möglichst eingeschränkte LiteLLM-Schlüssel. Provider-Schlüssel und virtuelle API-Schlüssel dürfen niemals im Angular-Frontend gespeichert werden.
